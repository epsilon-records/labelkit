# Catalogue to ERN 4.3 mapping

PR 1 of 3 for epsilon-records/labelkit#187: mapping only. Generator/download and XSD/fixture validation are separate PRs. No delivery, partner selection, commercial terms or catalogue migration is introduced.

Baseline: `src/lib/server/db/schema.ts` on main `7519e68`. The create stack adds entry surfaces, not the missing export facts identified here. This mapping also identifies losses a later importer must report rather than silently discard.

## Authority and validation boundary

Target the issue's **ERN 4.3**, namespace `http://ddex.net/xml/ern/43`, not the newer 4.3.2 dictionary. The [official ERN 4.3 XSD](https://service.ddex.net/xml/ern/43/release-notification.xsd) is the structural authority; [DDEX's preamble guidance](https://kb.ddex.net/implementing-each-standard/best-practices-for-all-ddex-standards/guidance-on-xml-issues/preambles-for-xml-based-ddex-messages/) explains namespace declarations. Prefix the root with `ern:` and keep its child elements unqualified, as specified by this XSD. Escape values with an XML writer. Do not concatenate unescaped catalogue text.

The official [allowed-value-set XSD](https://service.ddex.net/xml/allowed-value-sets/allowed-value-sets.xsd) currently identifies AVS version 12 (checked 17 November 2026). Validation PR 3 must pin the exact message and AVS bytes/checksums and use that AVS version explicitly, not a moving “latest” value. [DDEX's offline validation guidance](https://kb.ddex.net/general-implementation-guidance/validating-ddex-messages/offline-xml-validation/) explains the two schemas. Resolve the import to that pinned local AVS; disable arbitrary XML network access, external entities and DTDs.

XSD validity is not release-profile or partner acceptance. [DDEX's release-profile guidance](<https://kb.ddex.net/implementing-each-standard/electronic-release-notification-message-suite-(ern)/ern-4-explained/ern-4-profiles/>) describes the additional requirements. No release profile, variant or commercial deal is selected by this mapping. Findings distinguish `missing_required`, `unmapped`, `ambiguous` and `profile_required`; include the catalogue path, XML destination and affected record, without dumping unrelated tenant data.

DDEX retains copyright in its schemas. Its [licensing guidance](https://kb.ddex.net/general-implementation-guidance/licensing-the-standards/) permits development/testing under the automatically acquired evaluation licence and describes the implementation licence required before commercial production use. No schema text is vendored here and no terms are accepted or account created. PR 3 should fetch official schemas in CI with pinned hashes unless redistribution permission is established. Production licensing remains an Oracle/Nate gate; this document does not grant it.

## Tenant-safe export snapshot

An admin-only download must read through `locals.db`, for the selected membership's `orgId`. Join on both tenant and entity IDs; never fetch another tenant's parties by a global ID. Take one consistent snapshot of the release, its label, ordered tracks, recordings, approved credits, referenced parties, compositions and relevant rights/agreements. Never include Supabase identities, audit internals, billing, private master URLs or contract documents in the XML.

The source model has **no `territories` table**. Territory fields are strings on `rights_shares` and `agreements`, constrained to `WW` or two uppercase letters. The SQL constraint is not an ISO membership check. Do not treat every syntactically valid pair as a real territory.

### Credit roles

Against the pinned [AVS](https://service.ddex.net/xml/allowed-value-sets/allowed-value-sets.xsd), propose `main`→display MainArtist; `featured`→display FeaturedArtist; `remixer`→contributor Remixer; `producer`→Producer; `composer`→Composer; `mixer`→MixingEngineer; `mastering`→MasteringEngineer. Generic `writer` stays an ambiguity finding. Composition-writer roles retain their separate composer/lyricist/composer-lyricist/arranger meanings and require the appropriate allowed-value validation. No role is selected from a party's person/group/unknown kind.

A canonical artist-name rendering policy for multiple main/featured artists is not stored. Preserve the ordered parties and report the display-string gap; do not add guessed “feat.” punctuation or use a copyright line as an artist name.

## Required facts the current model cannot always supply

For the selected release plus sound-recording subtree, this is the missing-data checklist. Existing required names, UPCs, ISRCs, label links and track positions still need non-empty, tenant-consistent values; NOT NULL alone does not guarantee valid content.

| Gap                                             | Where it blocks                                                                   | Current source state                                                                                                                                                                       |
| ----------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| G01: Registered sender and recipient identities | Required header party IDs                                                         | No DDEX-party registry or export context. No partner has been selected.                                                                                                                    |
| G02: Metadata language                          | Required root language/script                                                     | No metadata-language column; performance language is also absent but is a different fact.                                                                                                  |
| G03: Recording type                             | Required sound-recording type                                                     | No column distinguishing music, speech or other recording kinds.                                                                                                                           |
| G04: Explicit-content classification            | Required release and recording warnings                                           | No explicit/clean/warning fields. Cannot use absence as a negative.                                                                                                                        |
| G05: Complete duration                          | Required recording duration                                                       | `duration_ms` nullable. Audio analysis may inform future data entry, but is not an automatic metadata override.                                                                            |
| G06: Complete display artists / display strings | Required release and recording artists                                            | Credits may be absent or unapproved; formatted artist-name text is not stored.                                                                                                             |
| G07: Release genre                              | Required release genre                                                            | Nullable. Do not fill from the first track or classifier without approval.                                                                                                                 |
| G08: Optional track-product prerequisites       | Required children if a track product is emitted                                   | Track-product identity/namespace missing; track genre nullable. Base XSD permits omitting track products; a later profile may not.                                                         |
| G09: Identifier namespaces                      | Required attributes if catalogue/proprietary identifiers are emitted              | Catalogue number exists; its controlling namespace does not. Omit with a finding or require explicit context.                                                                              |

| G11: Compilation marketing form                 | Required release type for compilation records                                     | Internal `compilation` does not identify an ERN marketing form; single-/multi-artist compilation flags are a separate optional choice.                                                     |

No additional mandatory child is created by emitting an otherwise empty optional composite. Empty lists must not hide absent facts. The generator must report all applicable gaps in one response and produce no misleading partial “valid” download.

Other **profile/partner** gaps: release-profile selection, P/C lines and years, artwork, audio file/package metadata, track products, commercial models, use types, sales territories, price/deal terms, availability windows and original-publication dates where required. Their requirement depends on the chosen profile or emitted composite; they are not all base-XSD requirements. LabelKit's release date, ownership splits and processing consents do not supply these facts. No DealList is emitted without actual commercial instructions.

## Next PR contracts and regression cases

PR 2 should expose a pure server generator taking an RLS snapshot plus explicit export context. It returns XML or structured findings, with no network or storage side effects. Admin permission is checked before reading; the download contains only the selected tenant/release. Supplying missing catalogue/export facts needs an agreed UI/configuration source before the admin action can generate a valid message. This mapping does not add fields or choose those values.

PR 3 should validate fixture-only output against official, checksum-pinned message/AVS XSDs and cover every M-rule and G-gap. Required cases include leading-zero UPC, XML-sensitive names, exact fractional duration, duplicate recording placements, two discs reusing position 1, missing/ambiguous artists, generic writer, invalid territories, overlapping rights, multiple works, cross-tenant IDs and absent sender/recipient/language/warnings. An XML that validates structurally must still fail when mapping would drop or invent catalogue facts. Never upload real catalogue XML to an external validator.

For the later ERN importer, these gaps are also loss reports: DDEX party identifiers, aliases, multiple territories/languages, product IDs, warnings, P/C lines, technical files and deal/controller semantics cannot be silently discarded into the current schema. Import dry run must show them before confirmation; this mapping grants no permission to change rights, contracts or artist pay.
